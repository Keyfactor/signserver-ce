SignServer Authentication and Authorization

In SignServer, client authentication and authorization can be configured per Worker and occurs in different components as the request comes in.

Reverse HTTP proxy

Optionally, before SignServer and the application server, a reverse proxy could be put in place for instance to perform the authentication.

The reverse proxy, such as Apache HTTP Server or Nginx, can be configured to perform the authentication and pass along the already authenticated information to the application server using for instance an AJP Connector. For information on how to configure a reverse proxy, see SignServer Integration.

Servlet Container

Provided by application server, the servlet container (web server) first receives the HTTP request.

The Servlet container provides the remote IP address and all the HTTP headers sent by the client (and/or) to any proxy in front of it.

If configured, the Servlet container may require TLS client certificate authentication. In this case, the Servlet container is performing the TLS authentication and then provides the authenticated certificate.

SignServer Servlet

The Servlet in SignServer receives the request and gathers all relevant information to pass along to the next component called "Process Session".

SignServer Process Session

Before processing the request, it invokes the Authorizer that has been configured for the requested Worker. If the Authorizer allows the request it is further processed, otherwise the processing stops.

Authorizer Implementation

To configure an Authorizer, define the property AUTHTYPE in your Worker as the fully-qualified name of the Authorizer. The configured Authorizer implementation decides if the request should be allowed or not given the provided information. The Authorizer could also consult its configuration and possibly external systems as well.

Examples of Authorizers:

Client Cert Authorizer

Checks that the certificate serial number and issuer DN from the provided client certificate is available in this Workers whitelist.

List Based Address Authorizer

Uses white or blacklists for the remote (IP) addresses to authorize.

Username Authorizer

Same as the List Based Address Authorizer, but the Username Authorizer can be used in a set up where the user is already authorized by the reversed proxy. The provided username is simply accepted and used further on.
The reversed proxy could use modules for Active Directory / LDAP authentication or anything else that in the end provides a user name to be passed on to SignServer.

Username Password Authorizer

Checks that the username/password provided in the HTTP Basic Authentication HTTP header matches one of those configured for this Worker.

All available Authorizers are listed on the Authorizers page.
